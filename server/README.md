# 拼豆小程序服务端

服务端包含微信登录与支付边界、商品目录、次数账本、图纸生成任务、人工真人 Q 版工单和兑换码管理后台。默认 `PAYMENT_MODE=mock`、`CUSTOM_SERVICE_MODE=disabled`，不会创建真实支付订单，也不会伪造支付成功。图纸任务继续使用项目现有的 MARD 逻辑；人工定制只有商家手动上传成品，不接入自动生图 API。

## 本地检查

```bash
cd server
pnpm install --frozen-lockfile
pnpm check
pnpm test
```

`pnpm test` 包含商品金额、上传格式及真实图片生成 smoke test，不需要微信密钥；生成 smoke test 使用项目内猫咪素材。`/health` 和静态管理后台可以在未配置数据库时启动检查，依赖 PostgreSQL 的接口则需要先运行数据库迁移。

## 数据库迁移

生产迁移前先做 PostgreSQL 备份，并在维护窗口按序执行：

1. `migrations/001_membership.sql`
2. `migrations/002_sessions_and_seed.sql`
3. `migrations/003_credits_and_payment_hardening.sql`
4. `migrations/004_restore_time_membership.sql`
5. `migrations/005_server_generation_products_admin.sql`
6. `migrations/006_manual_custom_orders.sql`

第 5 个迁移采用新商品 ID（`credits10_v2`、`credits30_v2`、`credits100_v2`、`permanent_v1`），金额分别为 888、1888、6666、8888 分；只新增商品和服务端任务/后台所需表字段，不改写旧订单、会员、兑换码和余额。永久卡是独立权益位，购买和兑换流程在服务端防止重复开通；仍有效的旧时长会员规则继续兼容。

## 启动与管理后台

复制 `.env.example` 为服务端私有 `.env.local`，至少设置 `DATABASE_URL`。应用启动后 `/health` 可供健康检查，后台入口为 `/admin`。首次建管理员前应先完成全部迁移，然后通过部署平台密钥设置 `ADMIN_BOOTSTRAP_USERNAME` 与至少 14 位的 `ADMIN_BOOTSTRAP_PASSWORD`，启动一次后可移除 bootstrap 密钥。后台使用 scrypt 密码哈希、HttpOnly/SameSite=Strict 会话、CSRF token、来源校验和登录尝试限流。不要把 `.env.local`、真实密码、支付密钥或数据库连接串提交进代码仓库。

兑换码明文仅在创建响应和页面当前会话中出现，数据库只保存 SHA-256 摘要；后台支持批次、失效时间、备注、查询和仅停用未兑换码。账户详情展示余额、永久权益、订单、兑换、生成任务和流水；管理员变更有审计记录。

## 人工真人 Q 版定制（默认不上线）

新页面位于 `subpackages/custom/`，首页与“我的”有入口。后台用户详情可授予/撤销“商家”“测试账号”身份，操作受现有管理员会话、CSRF、来源检查保护并写审计；商家所有工单及文件操作都由服务端重新校验角色，不能靠隐藏入口。现有兑换码和账户管理保持原样。

在商业决策确认前，只可设 `CUSTOM_SERVICE_MODE=test` 并通过 `/admin` 授予少量测试账号。`CUSTOM_CREDIT_COST` 留空时测试工单明确显示“免扣次”，不触碰余额；如测试扣次则必须显式设置成本。正式模式除明确正整数单价外还要求 `CUSTOM_COMMERCIAL_RULES_APPROVED=true`；永久卡与旧时长会员策略目前只能为 `excluded`，均不自动提供无限人工服务。真实上线前必须由运营方明确确认：每单扣几次、永久卡/旧会员是否包含此人工服务；还需确认交付时效、免费修改次数及已售权益文案，不得追溯变更承诺。未确定前不要设 live，也不要向真实客户开放接单。

客户先上传原图为私有暂存文件，明确填写人数、风格、特征、尺寸和第三方人工处理/监护人/扣次同意，再用 `Idempotency-Key` 创建工单。服务端锁定用户、检查可用次数并增加 `credits_reserved`，不记录正式消费；旧的直接制图账本和停用的 `/api/quota/consume` 不参与。商家接单、回复、上传 Q 图预览；客户确认或提出修改；商家上传最终 Q 图、高清施工图、用色清单三份文件后，同一数据库事务将文件设为可见、扣除实际次数、解除预占并写 `credit_ledger` 的 `MANUAL_CUSTOM/manual_q_custom` 项。拒单、待接单取消、服务端上传故障及超时清理会幂等释放预占。管理员特殊退次只能对已完成且未退款工单操作，必须填写原因，并分别写 `MANUAL_REFUND` 账本和后台审计。消息、状态操作及建单均有各自幂等键。

文件存储最小成本方案是单节点服务端**专用持久化挂载卷**：`CUSTOM_STORAGE_ROOT` 必须是仓库及公开静态目录之外的绝对目录，权限 `0700`；存储文件是随机名称且权限 `0600`，数据库记录所有者、工单、真实类型、大小、哈希和到期时间。上传仅允许单张不超过 15MB 的结构完整 JPEG/PNG/WebP；原图、聊天图和交付图都只通过带登录令牌的 `/api/custom/files/:fileId` 下载，不设公开 URL。生产部署须保证卷不会随容器重建丢失，数据库与卷一起备份并验证恢复；多实例部署应改用私有对象存储和服务端授权代理，不能把密钥写进小程序。没有这个持久卷时上传/接单不可用，本地 `/tmp` 不能当生产存储。

暂存上传 1 小时内未认领会清理；未终结工单超过 `CUSTOM_ORDER_TIMEOUT_DAYS` 无活动自动标为系统失败并释放预占；完成/拒单/取消后的全部私有文件在 `CUSTOM_RETENTION_DAYS` 天后清理。每天运行一次 `pnpm custom:cleanup`，监控运行结果并对数据库+文件卷做备份。工单元数据及记账/审计记录保留，不把客户照片或成品用于案例展示。用户界面明确告知商家会人工使用第三方图像工具处理照片；**实际使用 GPT 或其他第三方前**还需核实供应商、数据处理协议、境外传输/单独同意要求、未成年人专门规则以及微信小程序隐私指引。当前勾选与提醒不能替代运营方的合规核验。

上线前测试需准备至少两个真实微信测试账号（客户和商家）、已迁移的测试 PostgreSQL、HTTPS 测试域名和持久私有卷，再走“提交→回复→Q图预览→客户确认→三图交付→结算→下载”及“拒单→预占归还”。测试数据不可使用真实顾客照片。现有本地环境没有 `DATABASE_URL`、微信密钥或私有文件卷，`pnpm test` 只覆盖规则/文件结构/旧制图回归，不等同于数据库联调、微信开发者工具预览或真机验证。

## 图纸生成与计费

小程序只上传原图、制图参数和幂等键。服务端从会话确定用户，验证图片类型/大小与参数，事务预占次数后将原图交给受限 worker 队列。算法和 MARD 色板仍复用项目代码；服务端成功保存结果后才扣除预占，失败或超时则释放。相同幂等键只能用于完全相同的图与参数。接口 `/api/quota/consume` 已停用，不能用它替代服务端生成结果。生产部署须设置资源/并发限额、PostgreSQL 备份、HTTPS、日志保留和 worker 监控。

## 真实微信支付仍需人工配置

只有取得小程序与商户授权后，才配置 `WX_APPID`、`WX_SECRET`、`WX_MCHID`、API v3 密钥/证书文件、HTTPS 回调地址及合法域名；所有密钥放在服务端密钥管理或只读挂载文件中。支付回调继续执行现有验签、解密、金额/商户校验、订单锁和幂等发放逻辑。本工作区没有真实商户密钥、数据库连接或已部署服务，因此不能验证真实支付闭环；禁止将 mock 响应当作支付成功。

将 `pages/index/membership-config.js` 中的 `PAYMENT_CONFIG.mode` 设为 `live` 并填写已部署 HTTPS API 地址之前，先完成数据库迁移、微信合法域名、真实支付回调、幂等查单和失败恢复的联调。客户端提交商品 ID，不提交价格、次数或权益。
