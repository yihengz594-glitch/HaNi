# 全尺寸图像重建：实验阶段报告

## 状态

这是可运行、有对比结果的 Target Mode 试用实现，不是已经完成视觉验收的最终算法。
当前默认仍是 Legacy；显式 `generationMode: 'target'` 才使用新管线，目标模式由服务端版本标识。
未上传微信、未部署服务器、未改网站、UI、账号、支付或卡密逻辑。

## 1. 实际旧流程及原因

正式图片经小程序上传到服务器任务，再由工作线程调用
`server/src/pattern-core.js`；本地生成只在开发版且未配置后端时开放。
服务端使用现有Canvas解码，本地使用微信Canvas解码。

目标模式的所有尺寸统一走：读取原生像素 → 像素晶格/卡通/照片分析
→ 保守背景判断 → 紧凑构图 → 固定尺度类型与结构分析 → 按类型采样
→ 保边平滑与原图细线/高光证据恢复 → 局部感知颜色区域化
→ 真实 MARD 色号 → 去孤点与局部回退 → 同一格子矩阵用于预览、编辑、导出和统计。

Legacy 仍保留原来的小尺寸与大尺寸流程，未被新预处理触碰。

旧算法并非完全没有感知色差：大尺寸已经有OKLab距离，小尺寸有Lab。
因此不能把问题全部归结为“RGB最近色”。已确认的风险是：

- 大尺寸仍有误差扩散；常量0.52，但实际按格数降到0.42/0.32/0.24，
  肤色与深色细节还会进一步减弱。此前口头只说0.52不够准确。
- 全局RGB分箱及候选选择，没有局部连通区域制作成本目标。
- 暖色会被启发式肤色判断限制到肤色锚点，不能等同识别人脸。
- 没有通用、受关键区域保护的连通小岛清理。
- 两条 Legacy 尺寸路径仍不同；Target 内部已固定分析尺度，避免同一原图仅因
  输出为 52/80/100 格就改变类型和结构策略。

“今天突然变化”的线上原因未确认：未检查线上部署版本、历史任务输入及
具体生成设置。本报告证明当前基线可产生碎色，不证明某次线上版本事故。

## 3. 新实验流程

原生图片分析/已有像素格对齐 → 受限工作分辨率 → 属性分类
→ 边缘及显著性估计 → 双边保边平滑 → 按类型采样
→ 有原图证据的细线恢复 → 连通局部感知颜色分组
→ 带颜色新增成本的MARD匹配 → 近似颜色成本优化
→ 同步邻域优化 → 连通小区域清理 → 最终唯一格子矩阵。

平滑发生在目标格子采样之前；已有像素格不作双边平滑。图片类型与结构
使用固定分析尺度，再投影到不同输出尺寸。
没有全局饱和度增强，没有误差扩散，没有随机性，没有新画五官或强制对称。

## 4. 色差与减色

sRGB先线性化，再转OKLab。颜色成本包含OKLab距离、低色度保护、
色相方向偏差、增加色号的面积成本和邻近已用颜色不一致成本。
低饱和图片的近中性区域限制到所选色板中较中性的色号；有色眼睛和
鼻子仍能使用真正有色候选。MARD有限灰阶本身有微弱色偏，不能保证
屏幕上的每个原图颜色都有完全相同的豆色。

最终优化允许合并带来有限颜色误差，但保护显著的小特征。
这是软预算，不为达到一个数字强制删掉所有配饰。当前复杂华服仍超出
推荐色数，尚未达到用户的最少颜色目标。

## 5. 孤立豆和小块

四连通同色区域分析。普通区域<=3格，周围
至少65%的邻接边属于同一色号，且感知色差在安全阈值内，才合并。
明显高对比点、饱和色小特征、有两侧亮色证据的细线不合并。
3×3邻域至少6格同色且足够接近、不是强边缘，才替换。
所有清理读旧矩阵、写新矩阵，避免遍历方向造成逐步侵蚀。

这保护的是图像证据，不是经过模型确认的鼻孔/眼睛/首饰。

## 6. 分辨率和类型

resolutionFactor=sqrt(W*H)。推荐颜色基础预算14/22/30/38/46，按复杂度
调整；平滑半径、小岛面积和合并色差随尺寸改变。现有8–160格边界不变。
不会把用户选的72色偷偷改为221色，也不会增加格数。

已实现的是像素、扁平、卡通、低饱和、黑白及纹理图属性分流，并输出
真人、宠物、动漫、Q版、插画、黑白漫画、Logo、扁平图、风景、古风复杂插画、
低饱和度、高饱和度共 12 类启发式评分。
**这不是可靠语义识别**：真人、宠物、风景、古风仍不能仅凭传统统计量可靠区分。
主体权重目前是透明/已有背景判断加中心显著性先验；debug subject图不是
语义分割结果。没有真正的人脸、宠物脸、耳朵及眼睛检测器。
backgroundDetailFactor用于显著性较低区域的颜色成本，不能宣称已经准确分离复杂背景。

## 7. 对比验收

五张真实输入按相同原图、设置和 MARD 221 生成 32/52/80/100 格，共 20 对
Legacy/Target 无网格对照；另有 29、40、48、104、128、160 及矩形尺寸的
自动回归、透明 PNG、黑白图、色板范围、本地/服务端一致性和 Legacy 回归。
最新 57 项自动测试通过；语法/JSON/WXML 检查覆盖 40 个 JavaScript 文件、6 个页面。

100 格本次结果：

| 输入 | 颜色旧→新 | 单格连通小岛旧→新 | <=3格区域旧→新 |
|---|---:|---:|---:|
| 抱枕女孩 | 35→18 | 1790→482 | — |
| 黑白漫画 | 18→8 | 1897→431 | — |
| 灰猫 | 47→24 | 1331→241 | — |
| 银猫 | 37→15 | 1943→129 | — |
| 古风女孩 | 58→35 | 1461→754 | — |

猫图碎色下降，眼睛和鼻子仍可见；细毛被主动简化。
古风图碎色下降，但复杂纹样仍可能超出推荐色数，不能只报平均提升。
颜色数和单格小岛数只是辅助证据，最终仍需肉眼检查主体、五官和色块。

输出质量指标包括颜色数、单格小岛数、小区域数、平均区域面积、
边缘F1、颜色熵、碎片化率。边缘F1基于格子采样颜色的相邻高对比边界，
是代理指标，不是真实轮廓/人脸准确率，也不能替代肉眼验收。

五张输入均已纳入内部回归；统计只用于定位碎片变化，不能替代人工判断。

已生成AREA均匀积分近似、矩形BOX核、Lanczos3、Catmull–Rom Bicubic、
Median、Dominant同图52和104格对照（3×2×6=36组）。不宣称与任何
第三方库具体resize实现逐像素一致。默认纹理图选Median，卡通主色块

诊断输出有预平滑原像素、平滑图、edge/importance/subject估计图、
匹配后清理前及最终格子图，JSON保留前后矩阵和指标。

## 9. 性能、依赖和费用
